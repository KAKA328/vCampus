### 2.1 横向协作责任

本组为 5 人团队，不再单独设置网络、数据库、GUI 和测试专职角色，采用“模块负责人纵向负责、组长横向统筹”的方式：

- 何锦恒统一维护 `common` 协议、Socket 接入、会话授权、公共数据库命名和最终集成；
- 每个模块负责人同时负责该模块的界面、实体、数据库表、客户端逻辑、服务器端逻辑和测试；
- 涉及公共类、公共表、公共消息类型的修改，必须先在 Pull Request 中说明影响范围；
- 所有人共同参与联调、验收、项目报告和答辩，个人小结只记录本人实际完成的工作。

## 5. 每周进度报告填写格式

每周按以下四项记录实际情况，不要只写“正常”：

1. **进度**：正常、超前或滞后；列出已完成的接口、页面、表和测试数量。
2. **状态**：当前阻塞问题，例如 Access 驱动、接口冲突、Socket 断线或数据约束错误。
3. **计划**：下一周具体到模块、类、接口、表或测试用例的目标。
4. **建议**：负责人、解决时间和备用方案，例如先用内存 Repository 完成联调，再接入 Access。

## 7. 风险与处理

| 风险 | 处理方式 |
|---|---|
| 多人修改公共协议产生冲突 | 只由组长维护 `common`；其他成员提交接口变更 PR |
| Access 版本/驱动不一致 | 早期在验收机房验证；保留 Repository 接口和测试替身 |
| 单个模块延期阻塞集成 | 先交付接口 + 内存实现，再替换 Access 实现 |
| 密码和测试数据泄露 | 只使用脱敏演示账号；数据库不提交真实信息；密码使用哈希 |
| 最后阶段文档缺失 | 每周同步设计文档，第四周只做校对和排版，不从零开始写 |
