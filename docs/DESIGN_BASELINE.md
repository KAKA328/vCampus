# 设计基线

## 分层

`view` 负责界面，`biz/srv` 负责业务服务，`vo/domain/pojo` 负责可序列化实体，`dao` 负责数据访问。客户端通过 Socket 发送 `Message`，服务器端按消息类型分发到对应模块服务。

## 共享协议

`Message` 使用 Java 对象流传输，包含请求 ID、消息类型、状态码、发送者和负载。客户端与服务器端必须使用同一版本的 `common` 模块。

## 用户管理基线

- 开户：系统不提供登录页公开自助注册；账号由系统管理员开户注册或由初始化脚本预置，校验账号唯一、密码长度和角色合法性。
- 学籍绑定：创建学生账号时必须同步创建或绑定 `tblStudent`；创建教师账号时必须同步创建或绑定 `tblTeacher`。账号只负责登录，学籍、历史成绩和学业审查数据由学籍/教务模块维护。
- 注销：只能注销当前账号或由管理员执行，必须二次确认。
- 登录/登出：登录成功返回用户信息和会话令牌；登出使令牌失效。
- 授权：服务端校验角色和会话，不以客户端界面隐藏作为权限控制。
- 密码：示例内存实现使用 PBKDF2 哈希；正式 Access 实现不得存储明文密码。课程验收若在不可信网络运行，应在 Socket 外增加 TLS 或由教师确认网络边界。

## 数据库基线

表名使用 `tbl` 前缀；主键、非空、唯一和外键约束在设计说明书与建库脚本中保持一致。测试数据库必须包含可演示账号，禁止使用真实个人信息。

外部项目调研来源与本轮账号-学籍设计决策记录在 `docs/EXTERNAL_VCAMPUS_RESEARCH.md`，后续修改账号、学籍或开户注册流程时必须同步更新。
