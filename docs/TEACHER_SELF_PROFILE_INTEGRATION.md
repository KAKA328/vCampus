# 教师本人档案与学籍权限对接

2026-09-06 用户明确调整：教师在学籍模块不能查看授课班学生信息，只能查看本人教师档案及在职情况。本规则替代之前的“授课范围内可查询学生档案”。

## 已实现

- 教师登录后进入“教师信息”，显示“我的教师信息”：教师工号、绑定账号、姓名、院系、职称、在职/非在职。全部只读，无学生检索、学生列表、联系方式或保存按钮。
- 新消息 `TEACHER_SELF_QUERY_V1`，载荷 `TeacherSelfQueryV1Command(token)`，成功返回 `TeacherProfile`。没有可指定他人工号/账号的参数。
- 服务端按 token → 当前教师会话 userId → TeacherProfileService.findByUserId 查档案。sender 不作为身份依据。Access 启动读取同库 tblTeacher，内存启动提供绑定 demo_teacher 的示例。
- 未绑定返回 NOT_FOUND；非教师角色 FORBIDDEN；失效会话 UNAUTHORIZED；错误载荷/空 token BAD_REQUEST；数据库错误由教师服务映射 SERVER_ERROR。
- active=false 是非在职，仍可只读本人档案；账号停用或失效应由用户模块禁止登录/撤销会话，不把在职状态与登录账号状态混用。
- 教师访问所有 STUDENT_QUERY 查询类型和 STUDENT_UPDATE 均返回 FORBIDDEN，包括本人查询、存在/不存在学号、班级及专业。拒绝发生在读取学生档案前。原 TeacherStudentAccessPolicy 不再决定学籍学生查询授权。
- 学生本人成绩查询仍只允许学生，教师无法调用。

## 对选课方要求

不得再从教师客户端调用 STUDENT_QUERY 获取学生档案。学籍不再向教师账号提供学生个人资料。

选课模块的教师授课业务仍应独立校验身份、在职情况和教学班归属。TeacherProfileService/学生批量档案 Service 是服务端内部能力，不等于授权教师读取完整学生资料；如成绩导入/点名确需名单，请另行确认最小字段与用途，不得复用已撤销的学籍权限。此次未新增或扩展任何选课名单查询能力。

教师档案与课程安排仍使用同一 tblTeacher；非在职教师不能被安排新教学班的现有规则继续生效。

## 兼容与验收

客户端、common、student-management 和服务器配套更新；旧客户端教师查询学生会被服务器拒绝，不保留放行兼容路径。未改变旧命令的序列化字段，只新增独立 V1 消息与命令。

验证：教师只能读取绑定档案，伪造 sender 无效；非在职状态可见；未绑定不以同名工号兜底；登出后不可查；其他角色不可用该本人协议；教师对全部学生查询和修改被拒，即使授课策略返回允许；页面字段只读，查询失败清空旧信息。

## 审查修复：强制改密限制

TEACHER_SELF_QUERY_V1在读取本人档案前调用统一`authorize(token, USER_SELF_READ)`，再核对TEACHER角色。强制改密会话返回FORBIDDEN；完成改密后旧会话失效，重新登录才可读取。非在职但正常有效会话仍可读取本人状态。未新增其他角色或学生信息访问权。
