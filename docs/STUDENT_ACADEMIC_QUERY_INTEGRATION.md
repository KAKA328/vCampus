# 学籍成绩查询与选课对接要求

> 本轮补充：学生已新增 CREDITS 当前学分查询，教务已新增完整审查和人工毕业管理，详见 [三角色职责及毕业管理](ACADEMIC_ADMIN_GRADUATION_INTEGRATION.md)。下文保留最初课程历史对接阶段背景；成绩审核状态过滤仍待选课方实现。

核对日期：2026-09-06。开发基线：main `49d5448`；本次实现位于 `feature/student-academic-query-v1`，尚未提交或合并。

## 1. 本次已推进的学籍能力

- 新增 `STUDENT_ACADEMIC_QUERY_V1`，支持学生本人课程历史与待重修查询。
- 服务端从 token 查会话，再从 `tblStudent.user_id` 定位学号。请求没有学号、账号、教师编号或要求学分参数；消息 sender 不作为身份依据。
- 学生客户端在“学籍信息”中增加“成绩与重修”页签，包含课程历史、待重修切换及刷新。显示每次课程尝试，不在客户端自行累计学分。
- `AccessStudentSelectionProfileProvider` 保留选课方原有成绩 SQL 和独立待重修计算；此前改为调用学籍服务的改动及对应测试已按用户要求回退。
- 新查询沿用当前成绩表，不增加审核表或数据库字段，不写成绩或审核快照。

本次没有实现成绩审核或 APPROVED 过滤。当前数据库没有 `result_status`，不能把现有查询称作“已按审核状态过滤”。后续审核功能必须按第 4 节顺序联合发布。

## 2. 阅读选课代码后的实际调用链

Access 启动：

```text
CourseServiceFactory
 → CourseMessageHandler（会话与选课权限）
 → AccessStudentSelectionProfileProvider.findByUserId
    → tblStudent：账号绑定、专业、入学年份、学籍状态
    → tblSelectionRound：当前开放轮次学期，否则最近配置学期
    → 原选课侧 SQL：读取 course_id / passed，独立判断待重修
 → DefaultCourseSelectionService
    → 学籍状态、培养方案、轮次、教学班、容量、重复选课和课表冲突
```

`DefaultCourseSelectionService` 已基于服务端提供的待重修课程号，决定是否展示重修轮次及可选课程。没有选课轮次时，Access 选课资料返回 NOT_FOUND；学籍成绩查询不依赖轮次，即使当前不开放选课也可以查看成绩。

内存选课启动仍使用选课模块的演示资料；`StudentSelectionProfileAdapter` 是组合学籍 Service 的另一条入口，不能将它描述成当前所有 Access 启动的唯一入口。两种部署的数据源差异需在演示时明确，正式联调统一使用同一个 Access 文件。

另一个联调前置条件：当前 seed 没有选课轮次，示例学生为 2023 级、培养方案为 2026 级、教学班学期为 2025–2026–1。请选课方准备与目标学生入学年、推荐学期及当前轮次匹配的完整演示数据。原 seed 可直接验证学籍历史，但不构成完整选课演示；本次不擅自调整选课业务样例。

## 3. 新查询协议（可直接接入）

| 项目 | 契约 |
|---|---|
| 消息 | `STUDENT_ACADEMIC_QUERY_V1` |
| 请求 | `StudentAcademicQueryV1Command(token, QueryType)` |
| QueryType | `HISTORY`、`PENDING_RETAKES` |
| 成功响应 | `OK + List<CourseHistoryRecord>`；无成绩/无待重修时为空列表 |
| 角色与权限 | 仅 `STUDENT` 且具有 `STUDENT_READ`；只读本人 |
| 无效/退出会话 | `UNAUTHORIZED` |
| 其他角色 | `FORBIDDEN`，包括持有档案读权限的教师、管理员；这是学生本人专用协议，不代替教务查询协议 |
| 未绑定学生档案 | `NOT_FOUND`，不能以账号和学号碰巧相同兜底 |
| 错误请求类型、空 token、缺 queryType | `BAD_REQUEST` |
| 数据库失败或不可表达的成绩数据 | `SERVER_ERROR`，不伪造空列表或零分 |

客户端与服务器需要配套升级。旧 `STUDENT_QUERY` / `STUDENT_UPDATE` 语义、命令类和序列化版本保持原状；新命令独立版本化。Java Service 接口继续供同进程选课代码调用，不要求绕道 Socket。

教师与教务读取他人成绩的授权范围需要单独设计。不能把教师的“授课范围学生档案读取”扩展成该学生所有课程成绩的读取权。

## 4. 请选课负责人提供的接口与合并前置条件

| 对接事项 | 选课/教务方需确定和实现 | 学籍方接入动作 |
|---|---|---|
| 成绩草稿 | 批次及明细表、导入校验、本人教学班与有效名单验证 | 继续提供教师档案和学生批量查询接口 |
| 正式结果字段 | `result_status`、`source_submission_id` 的最终名称、类型、空值规则和状态集合 | 在 `historyFor` 统一过滤有效 APPROVED，待重修和实时审查沿用该入口 |
| 审核事务 | 通过时整批写正式结果，退回不写，重复提交/重复审核不得产生重复结果 | 测试审核前不可见、审核后完整可见 |
| 撤回与重审 | 更新为 REVOKED 或生成版本；有效版本唯一性、attempt_no 是否改变 | 撤回后重新计算学分和待重修，不缓存旧资格 |
| 历史数据 | 重建 seed/历史导入如何赋 APPROVED、来源能否为空 | 同步真实 Access 测试数据；不依赖旧库迁移链 |
| 学分规则 | 通过学分来源；同课程多次通过取最新或最高；补考、免修和部分学分 | 统一内存和 Access 聚合；确认前保持现有规则 |
| 阶段审查 | 要求学分从培养方案还是教务配置取得，适用专业/年级与时间 | 再添加服务端阶段审查请求，不接收学生自报要求学分作审核依据 |
| 审查快照 | 完整快照字段及唯一写入方，特别是 passed_course_count | 修复 latestReview 混合旧快照和当前通过课程数，并统一内存“最近计算结果”和 Access“持久化审核快照”的语义后再开放页面 |

**合并与发布顺序：**双方先确认字段和规则；选课方提交 schema/seed、审核写入实现，学籍方基于相同变更补正式状态过滤及回归测试。联合验收后配套部署。不能先上线会把未审核/撤回数据写入可读成绩表的写入端，再等待学籍过滤补丁。

### 空成绩兼容要求

当前 `CourseHistoryRecord` 的 score 是 0–100 的整数，无法表达 NULL。旧 Access 实现把 NULL 转成 0，本次已改为整体返回 SERVER_ERROR，防止“未录入”被显示为真实零分，或据此生成重修资格。真实 0 分仍正常返回。

该保护会影响含 NULL 成绩的学生：学籍课程历史、待重修、实时审查返回错误；选课侧已恢复原独立计算，不因这次学籍 NULL 分数校验而改变行为，直到数据被正确补齐。不能伪造 0 来绕过。当前草稿不得存进被读取的结果表；如免修等正式结果允许无数值成绩，需要双方另定可空分数/成绩类型的版本化 DTO 与计算规则。本次不擅自改变现有 DTO 字段含义。

## 5. 联调验收矩阵

本次应通过：

- 不同登录账号和学号正确绑定；伪造 sender 不影响本人身份；未绑定和已登出正确报错。
- 非学生角色不能使用本人查询；空历史成功返回空列表。
- 历史首修失败后重修通过，该课程不再待重修；多个失败尝试只产生一个待重修课程。
- 正常成绩下，学籍和选课各自实现相同的待重修业务口径；异常数据处理不保证一致，后续由双方约定。
- NULL 分数与非法分数返回错误；真实 0 分保持原值。
- 使用正式 schema.sql + seed.sql 创建临时 Access 库，种子已包含当前学期开放轮次和重修演示数据；重修学生可直接读取 1 条课程历史和 1 条待重修课程，普通学生的空历史仍返回空列表。
- 页面查询失败清除旧数据，旧异步响应不能覆盖新查询；无数据、未绑定和错误状态可区分；表格不可编辑。

审核模块落地后追加：DRAFT/PENDING_REVIEW 不可见，APPROVED 可见，RETURNED 不写正式结果，REVOKED 不计学分；撤回唯一通过记录后按剩余有效记录恢复待重修；重审不会重复累计；历史导入和特殊成绩按已确认规则处理。
