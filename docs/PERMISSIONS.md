# 角色权限与数据范围基线

本文档是客户端导航、服务器授权和各业务模块对接时共同遵守的权限基线。角色是用户在整个系统中的身份，不会因为进入商店或图书馆而改变。

## 1. 最终权限矩阵

| 角色 | 学籍 | 选课 | 图书馆 | 商店 | 用户管理 |
|---|---|---|---|---|---|
| 学生 `STUDENT` | 仅本人 | 查询、选课、退课 | 查询、借阅、归还 | 查询、购买 | 仅本人账号 |
| 任课教师 `TEACHER` | 授课范围查询 | 课程查询、授课名单、成绩录入 | 查询、借阅、归还 | 查询、购买 | 仅本人账号 |
| 教务管理员 `ACADEMIC_ADMIN` | 学籍维护、学业审查 | 开课、容量、成绩复核 | 无 | 无 | 无 |
| 图书管理员 `LIBRARIAN` | 无 | 无 | 查询、借阅及图书管理 | 无 | 无 |
| 商店管理员 `STORE_MANAGER` | 无 | 无 | 无 | 查询、购买及商品管理 | 无 |
| 系统管理员 `ADMIN` | 全部 | 全部 | 全部 | 全部 | 用户、角色、注销和审计 |

## 2. 权限编码

| 权限编码 | 含义与数据范围 |
|---|---|
| `USER_SELF_READ` | 查看和维护当前登录用户自己的账号信息 |
| `USER_MANAGE` | 系统管理员维护用户、角色、注销和审计 |
| `STUDENT_READ` | 查询学籍；学生限本人，教师限授课范围，教务管理员可维护范围内查询 |
| `STUDENT_WRITE` | 教务管理员维护学籍 |
| `COURSE_READ` | 查询课程或名单；具体可见数据仍按角色和授课关系过滤 |
| `COURSE_SELECT` | 学生为本人选课或退课 |
| `COURSE_MANAGE` | 教务管理员开课、修改课程容量和停开课程 |
| `GRADE_WRITE` | 任课教师录入自己授课课程的成绩 |
| `ACADEMIC_REVIEW` | 教务管理员进行成绩复核和学业审查 |
| `LIBRARY_READ` | 查询图书和允许范围内的借阅记录 |
| `LIBRARY_BORROW` | 为当前用户借阅、归还图书 |
| `LIBRARY_MANAGE` | 图书管理员维护图书、库存和借阅记录 |
| `STORE_READ` | 查询商品、库存以及允许范围内的订单 |
| `STORE_PURCHASE` | 当前用户以自己的身份购买商品 |
| `STORE_MANAGE` | 商店管理员维护商品、库存和订单 |

## 3. 课程维护公共消息

| `MessageType` | 要求权限 | 用途 |
|---|---|---|
| `COURSE_CREATE` | `COURSE_MANAGE` | 创建课程或开课记录 |
| `COURSE_UPDATE` | `COURSE_MANAGE` | 修改课程信息、容量或开课状态 |
| `COURSE_DEACTIVATE` | `COURSE_MANAGE` | 停开课程；存在选课或历史记录时不得直接物理删除 |

具体命令对象和业务实现由选课模块提供。所有改变状态的请求都必须携带会话 token，并由服务器在调用 Service/Repository 之前授权。

## 4. 强制规则

1. `TEACHER` 和 `STUDENT` 在商店中是买家，但系统角色保持不变。
2. `STORE_MANAGER` 不具有 `COURSE_READ`、`COURSE_SELECT` 或 `COURSE_MANAGE`，客户端不得显示选课入口。
3. 客户端隐藏入口只是界面优化，不能替代服务端授权。无权限用户伪造请求时，服务器必须返回 `FORBIDDEN`。
4. 权限编码只表示操作能力，数据范围必须再次检查。服务器不能直接信任 payload 中的 `studentId`、`teacherId` 或 `userId`。
5. `ADMIN` 保留全部权限，用于系统维护和验收。当前实验版公开注册允许选择所有已定义角色，便于成员联调和验收演示；正式系统应改为由系统管理员创建或分配高权限账号，普通自注册只创建低权限账号。
6. 同一账号同一时间只允许存在一个活动会话。已登录账号再次登录时服务器返回 `CONFLICT`；正常登出、账号注销或服务器重启后可重新登录。
