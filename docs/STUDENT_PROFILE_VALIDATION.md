# 学籍档案输入规范

适用：管理员/教务编辑学生档案，以及学生保存本人联系方式。以下规则由页面和服务端共同执行。

| 字段 | 输入规范 |
|---|---|
| 学籍状态 | 管理员从“在读、休学、退学”下拉列表选择，不能手输；已毕业档案显示“毕业”且状态不可编辑，毕业仍通过毕业管理办理 |
| 性别 | 固定选择“男、女、未知”；学生端只读，原未配置字段可保持空 |
| 手机号 | 可不填写；填写时必须为11位ASCII数字，不接受字母、空格、区号加号或全角数字；输入阶段最多11位，保存时检查完整长度 |
| 邮箱 | 可不填写；填写时检查基本邮箱格式，最多100字符，不允许空格/控制字符 |
| 入学年份 | 4位数字，1900年至当前年份的下一年；服务端使用相同范围 |
| 姓名 | 必填，不能只填空白，最多64字符 |
| 院系、专业 | 延续原可空规则，最多64字符，不允许换行或控制字符 |
| 班级 | 延续原可空规则，最多32字符，不允许换行或控制字符 |
| 学号、绑定账号 | 已加载档案表单中只读，避免误改学生身份；服务端普通档案写入校验长度不超过32且仅字母、数字、下划线、短横线 |

说明：这里校验手机号的字符和位数，不判断号段是否真实分配；不验证邮箱真实存在。学号允许现有STU-001/demo_student等标识，不擅自规定统一学号位数。

页面允许逐字编辑和删除，手机号少于11位时可以继续输入，但不能保存。粘贴超长或含非数字内容时整体拒绝，显示明确提示，不静默截断成另一个号码。加载历史非法号码时原样显示，保存前需修正或明确清空；不自动修改数据库已有记录。未知历史学籍状态在下拉框中不自动映射，管理员保存前必须选择合法状态。

校验位置：StudentProfileValidation为统一规则；StudentManagementPanel提交前调用；StudentMessageHandler与DefaultStudentManagementService.saveIfUnchanged/updateContacts再次校验。失败返回BAD_REQUEST，不写数据库。学生只校验可修改的联系方式，不因旧档案中只读字段缺失阻止其修正联系方式。

底层Repository及旧内部save保留初始化/内部调用兼容，不在此次直接改动其他模块的账号导入、选课规则或数据迁移；这些入口若接收新的外部档案数据，应另行对接同一校验。现有条件写入与毕业并发检查保留，格式正确不代表绕过身份权限或毕业流程。

无需数据库结构变更。本次已适配最新 main `63be10f`：主线新增成绩审核闭环、验收数据库和 `UiMetrics` 客户端缩放规范；本页面将间距、断点和表格宽度转换为 `UiMetrics` 逻辑尺寸。首页、选课及其他子系统未改动。此次未提交或推送。

## 专项测试数据与导入

测试数据分为档案数据和登录账号，必须按以下顺序准备：

1. 在仓库根目录执行以下命令，创建独立测试库并依次加载 `schema.sql`、`seed.sql` 和 `student-test-data.sql`。如目标文件已存在，脚本会先生成带时间戳的备份再重建。专项脚本新增 3 个学生档案、2 个教师档案和 4 条课程结果，不覆盖默认演示数据。

   ```powershell
   .\database\rebuild.ps1 -DatabasePath database\student-test.accdb `
       -AdditionalScript database\student-test-data.sql
   ```

   启动服务端时使用 `--db database/student-test.accdb`，不要连接日常使用的 `vCampus.accdb`。
2. 使用 `demo_admin / Demo123` 登录，进入“用户管理 → 批量导入”，选择 `test-data/学籍账号批量导入示例.csv`，预览无误后执行导入。
3. CSV 的“档案编号”列用于把登录账号绑定到已有学生学号或教师工号。缺少对应档案、档案已经绑定或重复导入时，服务端会拒绝该行。

专项档案场景：

| 档案编号 | 场景与预期 |
|---|---|
| `test_student_enrolled` | 在读；6 学分、2 门通过、1 次历史重修、当前无待重修 |
| `test_student_leave` | 休学；0 学分、1 门待重修，不允许办理毕业 |
| `test_student_withdrawn` | 退学；无成绩，不允许办理毕业 |
| `test_teacher_active` | 在职教师，可作为教学班教师候选 |
| `test_teacher_inactive` | 非在职教师，不能安排新教学班 |

CSV 提供其中 3 个可登录账号，初始密码统一为 `Test123`：

| 登录账号 | 角色 | 绑定档案 |
|---|---|---|
| `student_enrolled_01` | 学生 | `test_student_enrolled` |
| `student_leave_01` | 学生 | `test_student_leave` |
| `teacher_active_01` | 教师 | `test_teacher_active` |

学生登录后直接查看本人档案和学业信息；教师登录后进入“教师信息”即自动加载本人档案，右上角可刷新。教务管理员使用 `demo_academic_admin / Demo123` 查看全部档案、学分审查和毕业管理。专项 SQL 与账号 CSV 均只应在同一测试数据库中导入一次。
