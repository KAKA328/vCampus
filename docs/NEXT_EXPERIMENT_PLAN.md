# 后续实验推进计划

> 本计划基于 2026-08-26 GitHub 最新 `main` 整理，用于指导后续编码、联调和验收准备。

## 实验 E1：主线同步与安全分支

- 从最新 `main` 新建短期功能分支，不在旧分支上继续叠加改动。
- 每次合并前运行 `mvn clean test`。
- 修改公共协议、角色权限、数据库字段时，必须同步更新 `docs/INTERFACES.md`、`docs/PERMISSIONS.md` 和 `database/README.md`。
- 合并其他子系统 PR 前，把“是否新增 `MessageType`、权限、跨模块接口、服务器 Handler、客户端调用和测试”作为固定流程点；缺一项不直接进 `main`。

## 实验 E2：用户会话与重复登录

- 当前状态：已完成代码与自动化测试。
- 同一账号同一时间只允许一个活动会话。
- 已登录账号再次登录时返回 `CONFLICT`。
- 用户登出、自注销或管理员注销后释放活动会话。
- 补充自动化测试，覆盖重复登录、登出后重新登录、注销后 token 失效。

## 实验 E3：GUI 布局与主界面优化

- 当前状态：已完成首页卡片自适应换行、滚动区域和注册窗口可调整大小；后续还需要继续美化各子系统页面。
- 登录、注册、主界面使用统一字体、颜色、按钮和间距。
- 首页模块卡片说明文字随窗口宽度换行。
- 首页内容区域支持滚动，避免窗口缩放后卡片显示不全。
- 注册窗口允许调整大小；后续模块页面统一采用“标题区 + 查询区 + 表格区 + 操作区 + 状态栏”。

## 实验 E4：学籍档案与学业审查数据

- 当前状态：已完成学生基础档案字段、历史课程记录和内存版学业审查计算骨架；后续需要接入 Access 数据库、服务器消息和 Swing 页面。
- 注册只创建登录账号，不自动生成完整学籍档案。
- 学生基础信息由 `tblStudent` 保存，并通过 `user_id` 与账号关联。
- 教师基础信息由 `tblTeacher` 保存，并通过 `user_id` 与账号关联。
- 历史选课、首修、重修、成绩、是否通过和获得学分由 `tblCourseResult` 保存。
- 学业审查结果由 `tblAcademicReview` 保存，统计累计学分、挂科门数、重修门数和毕业条件。
- 自注册学生未关联学籍档案时，客户端提示“暂无学籍档案，请联系教务管理员维护”。

## 实验 E5：选课管理与成绩录入

- 教务管理员实现开课、修改容量、停课。
- 任课教师只能录入本人授课课程的成绩。
- 教务管理员可复核成绩并触发学业审查。
- 服务器端必须校验 `COURSE_MANAGE`、`GRADE_WRITE`、`ACADEMIC_REVIEW` 以及授课/学籍数据范围。

## 实验 E6：五模块联调

- 学籍、选课、图书馆、商店、用户管理均接入服务器 Handler 和客户端 Swing Panel。
- 每个模块至少包含正常流程、异常流程和权限拒绝流程。
- 学生、教师、教务管理员、图书管理员、商店管理员、系统管理员分别使用不同演示账号验收。

## 实验 E7：最终发布与验收

- 生成可独立运行的 `vCampusServer.jar` 和 `vCampusClient.jar`。
- 准备 `vCampus.accdb`、建库脚本、演示数据和使用说明。
- 生成 JavaDoc HTML。
- 补全软件设计说明书、项目进度计划报告、小组报告、个人小结和互评表。
