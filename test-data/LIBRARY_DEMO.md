# 图书馆测试数据与 UI 检查

馆藏数据由 `database/seed.sql` 维护，内存演示目录也包含同样的 B001–B050 共 50 种图书，覆盖文学、科幻、计算机、历史、教材、哲学、艺术、经济、自然科学 9 类。服务器使用 `--db` 时只读取指定的 Access 文件，不会自动把新 `seed.sql` 写入旧数据库；只更新客户端或重新编译，不能更新旧库中的馆藏。

## 准备一个独立测试库

在最新项目根目录执行以下命令。先按仓库 README 配置好 JDK 8 和 Maven：

```powershell
mvn -DskipTests package
& .\database\rebuild.ps1 -DatabasePath .\database\demo\library-demo-50.accdb
```

该路径与默认的 `database/vCampus.accdb` 及先前的 `database/demo/library-demo.accdb` 分开，不覆盖原有业务数据。若重复生成同一测试库，请先关闭连接它的客户端和服务器；重建脚本会备份该测试库，再按最新 schema 和 seed 重建。不要对有需要保留的业务记录的数据库直接重新执行整份 seed。数据库文件是本地产物，不需要提交到 GitHub。

在两个终端中分别启动（客户端、服务器使用同一次构建的 JAR）：

```powershell
java -jar .\server\target\vCampusServer.jar --db .\database\demo\library-demo-50.accdb --port 19090
java -jar .\client\target\vCampusClient.jar --host 127.0.0.1 --port 19090
```

进入图书馆后，关键词留空、分类选择“全部分类”，点击“查询图书”。统计应为 **50 种、147 册可借**；表格可上下滚动查看 B001–B050。50 种书共有 150 册，其中 3 册有未归还的演示借阅。这里的“50 种”指 50 条不同书目的记录，不是只准备 50 册复本。

## 本轮交互验收

- 详情：选择长书名、出版社或位置内容较长的图书打开详情；缩小对话框后各行不重叠，长值换行，超高内容可滚动，窗口可拉伸。新增图书表单也可滚动，输入有误后保留内容供修改。
- 分类：查询区选择“文学”“科幻”等下拉项；“全部分类”取消分类限制。新增图书也使用分类下拉框，已读到的旧库自定义分类会补入候选项。
- 旧书补库存：馆员选择 B001，点击“增加库存”，填写新增 `5` 册。在未做其他借还操作的初始库中，总量从 3 变为 8，可借从 2 变为 7；借出数量仍为 1，书号、价格和借阅记录保持不变。刷新或重启服务器后结果仍保留。0、负数、非整数不允许；学生、教师即使直接请求接口也不得补库存。
- 处理提醒：学生点击“去归还”，跳到“我的借阅”并选中最早到期记录；核对后点击“归还选中记录”，成功刷新后对应提醒消失。点击“今日已读”只收起本机当天已有提醒，不代表已还书；刷新、切换页面或重新登录不重复显示同一提醒。次日刷新、出现新记录、应还日变动或进入逾期阶段时重新提示。教师同样适用。
- 提醒隔离：不同账号、不同服务器地址/端口的已读状态互不影响。已读保存在用户目录下 `.vcampus/library-reminders` 内的本地配置文件，不跨设备同步；系统限制写入时回退为本次客户端进程内记忆。窗口跨午夜保持打开时，最多一分钟内会按新日期恢复提醒。

补库存使用新增 `LIBRARY_RESTOCK_V2` 消息，客户端和服务端须使用本次一起构建的版本；原有消息语义和数据库结构不变。若提交补库存时断线，先刷新核对库存再决定是否重试，避免重复增加。

### 布局与缩放检查

按 `docs/UI_DEVELOPMENT_GUIDE.md`，图书馆页面的间距、尺寸、表格列宽、表单和渲染器边距使用 `UiMetrics`，继续复用 `VCampusTheme`。筛选项标签与输入框成组换行，统计卡片按宽度排列，长说明和提醒自动换行，表格维持最小列宽并支持横向滚动。

自动测试覆盖师生与管理员的不同入口、420/1000 逻辑宽度下的工具栏边界、表格最小列宽，以及长提醒换行。交付前仍需在实际 Windows 客户端确认 100% 与 125%/150% 显示缩放、宽/窄窗口、详情与新增图书对话框；离屏预览不能代替实际显示器 DPI 验证。

如果仍只显示 3 本或 10 本，依次检查：是否清空关键词并选择“全部分类”；服务器连接的 `--db` 绝对路径是否是刚生成的 `library-demo-50.accdb`；19090 端口是否仍由旧服务器占用；客户端和服务器 JAR 是否来自当前构建。SQL 可核对 `SELECT COUNT(*) FROM tblBook`，预期为 50；`SELECT SUM(total_copies), SUM(available_copies) FROM tblBook` 初始预期为 150、147。不要为解决显示数量问题直接覆盖有真实业务记录的数据库。

`DemoCatalogTest` 检查 50 个连续且唯一的书号、唯一书名/ISBN 演示编码、9 类馆藏、总册数与可借册数，以及 SQL 与内存演示目录全部字段的一致性。借阅、归还或补充复本后统计会相应变化，不应再要求等于初始数值。
