# 图书馆测试数据与 UI 检查

馆藏数据由 `database/seed.sql` 维护，内存演示目录也包含同样的 B001–B010 共 10 种图书。服务器使用 `--db` 时只读取指定的 Access 文件，不会自动把新 `seed.sql` 写入旧数据库；只更新客户端或重新编译，不能更新旧库中的馆藏。

## 准备一个独立测试库

在最新项目根目录执行以下命令。先按仓库 README 配置好 JDK 8 和 Maven：

```powershell
mvn -DskipTests package
& .\database\rebuild.ps1 -DatabasePath .\database\demo\library-demo.accdb
```

该路径与默认的 `database/vCampus.accdb` 分开。若重复生成同一测试库，请先关闭连接它的客户端和服务器；重建脚本会备份该测试库，再按最新 schema 和 seed 重建。不要对有需要保留的业务记录的数据库直接重新执行整份 seed。

在两个终端中分别启动（客户端、服务器使用同一次构建的 JAR）：

```powershell
java -jar .\server\target\vCampusServer.jar --db .\database\demo\library-demo.accdb --port 19090
java -jar .\client\target\vCampusClient.jar --host 127.0.0.1 --port 19090
```

进入图书馆后，关键词与分类均留空，点击“查询图书”。统计应为 **10 种、27 册可借**；表格可上下滚动查看 B001–B010。10 种书共有 30 册，其中 3 册有未归还的演示借阅。

## 演示账号和操作

以下仅为项目公开测试账号，初始密码统一 `Demo123`。

| 账号 | 页面与初始状态 | 检查操作 |
|---|---|---|
| demo_student | 读者端；本人 3 条记录，2 条借阅中；B001 在建库日后 2 天到期 | 空条件查询 10 本；关键词“活着”返回 B009；分类“计算机”返回 5 本；借阅 B009 后刷新库存和本人记录；归还 B001 后临期提醒更新 |
| demo_teacher | 同一读者端；B002 在建库日前 2 天已到期 | 查看本人逾期提醒；归还 B002；无法看到管理员新增图书和全校记录入口 |
| demo_librarian | 管理员端；全校 4 条记录、3 条借阅中 | 查看价格与馆藏位置；查询全校借阅；代办归还；用新编号 B011 录入馆藏（新增后会超过 10 种，重复演示前可重建独立测试库） |

4 条借阅记录覆盖：临期、普通借阅、已归还、逾期。时间由建库日计算，持久化后会正常推移；演示前重建独立测试库可以恢复上述初始场景。内存模式每次启动重新计算日期。

## UI 规范对照

按 `docs/UI_DEVELOPMENT_GUIDE.md`，图书馆页面的间距、尺寸、表格列宽、表单和渲染器边距使用 `UiMetrics`，继续复用 `VCampusTheme`。筛选项标签与输入框成组换行，统计卡片按宽度排列，长说明和提醒自动换行，表格维持最小列宽并支持横向滚动。

自动测试覆盖师生与管理员的不同入口、420/1000 逻辑宽度下的工具栏边界、表格最小列宽，以及长提醒换行。交付前仍需在实际 Windows 客户端确认 100% 与 125%/150% 显示缩放、宽/窄窗口、详情与新增图书对话框；离屏预览不能代替实际显示器 DPI 验证。

如果仍只显示 3 本，依次检查：筛选条件是否为空；服务器连接的 `--db` 绝对路径是否是刚生成的测试库；19090 端口是否仍由旧服务器占用；客户端和服务器 JAR 是否来自当前构建。SQL 可核对 `SELECT COUNT(*) FROM tblBook`，预期为 10。
