## 一、生成可以复用的独立验收库

在本分支仓库根目录、JDK 8 + Maven 环境执行：

```powershell
mvn package "-DforkCount=0"
powershell -ExecutionPolicy Bypass -File scripts/New-LibraryAcceptanceData.ps1 -Output database/demo/library-acceptance-20260914.accdb
```

默认基准日期 T 是生成当天。验收延期请用**新文件名重新生成**；复现历史日期可加 `-BaseDate 2026-09-14`。界面按客户端当天日期计算提醒，手工验收应让 T 与各机器当天一致，不要修改系统时钟。脚本固定默认在借上限为 5；启动验收服务器也须使用 5。

输出文件已存在就拒绝，绝不删除、重建或覆盖它。失败输出保留诊断，不能用于演示；换新文件名重试。独立输出在 `database/demo/`，不提交二进制数据库。其他成员拉取 PR 分支、构建后执行同一脚本即可得到等价场景，实体册号/账单号/记录号使用正常 UUID，无需相同；通过固定账号和书号定位。

初始数据应为：**80 种书（原 50 + 专项 30）、31 个账号（原 12 + 专项 19）、25 条借阅（原 4 + 专项 21）、5 张赔偿单（4 待支付、1 已结清）、25 条书名快照、80 个副本初始化标记**。初始仅 `li_paid` 有一笔专项图书赔偿扣款；钱包起始余额是种子资金，不伪造充值流水。全库保留原 105 种商店商品和原始其他模块样例。

生成器完成前校验实体册、库存、借阅与快照关联；不会把负库存、重复占册、孤立记录等坏数据混入正常演示库。需要破坏性/故障场景时使用自动测试的临时库。

## 四、多客户端并发清单

验收架构限定为**一台服务器进程 + 一个 Access 文件 + 多台客户端**，不要让每位组员各自启动服务器，也不要让多个 Java 服务器同时写同一个共享盘上的 accdb。进程内共享锁不是分布式锁。

| 编号 | 并发请求 | 必须核对的最终结果 |
| --- | --- | --- |
| C01 | li_race01..08 同时借 LI-LAST | 恰好 1 成功、7 库存冲突；库存 0、1 条有效借阅、1 册被占用 |
| C02 | 8 个用户同时借 LI-MULTI | 恰好 3 成功；库存 0，3 个不同实体册，失败用户无借阅 |
| C03 | 同一有效 token 8 次借同一书 | 仅 1 笔有效借阅；其余重复/库存冲突，不额外占册 |
| C04 | li_quota4 同 token 并发请求不同书 | 仅 1 个新增成功，最终在借 5；无超过上限 |
| C05 | 8 次归还同一 LI-RACE-RETURN 借阅 | 仅首次成功；副本和库存只恢复一次 |
| C06 | 对 LI-RACE-LOSS 同一记录并发归还/确认遗失 | 只能归还或遗失一个分支提交，不能既恢复库存又产生赔偿 |
| C07 | 重复确认遗失 LI-RACE-PAY，再并发支付同一账单 | 重复请求可幂等返回成功，但同一账单/一次减总量/一次扣款/一条流水 |
| C08 | 8 个基于同一旧版本的管理员资料编辑 | 恰好一个成功，其余冲突，最终资料完整且库存不变 |
| C09 | 同账号先后在两台机器登录 | 后登录使旧 token 失效是用户模块策略；多用户抢书须用不同账号，不应误报库存并发错误 |
| C10 | 补库与借还、批量抢最后一册、钱包与商店操作 | 观察库存与副本、批量全成或全败、余额与流水一致；现有仓库级回归及人工共享钱包联调覆盖，非本轮 TCP 吞吐压测 |

C03/C04/C05/C07 使用**同一次登录所得 token**发并发请求；不通过重复登录制造多个有效会话。自动化用真实 ServerApplication、8 个工作线程、独立 TCP Socket、正式序列化消息与会话权限、临时 Access 数据库，所有结果再用新仓库连接读取，并检查完整副本关联。不是仅调用内存函数。

现场运行（先生成数据，确认端口无旧服务器，双方使用同一分支构建的 JAR）：

```powershell
# 服务器机器；只启动这一份服务
java "-Dvcampus.library.maxActiveLoans=5" -jar server/target/vCampusServer.jar --db database/demo/library-acceptance-20260914.accdb --port 19090

# 每台客户端，将占位符替换为服务器局域网/组网 IPv4
java -jar client/target/vCampusClient.jar --host <服务器IPv4> --port 19090
```

客户端不能把 127.0.0.1 当作另一台机器的地址。先检查同网段/组网连接和服务器入站防火墙是否允许 TCP 19090；不需要公网开放端口，本次没有自动修改系统防火墙。验收前让所有客户端从各自界面刷新相同目录，协调倒计时点击借阅；失败用户刷新后应看到最新库存，自动测试比手动同时点击更可重复。
