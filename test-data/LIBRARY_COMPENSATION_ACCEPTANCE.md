## 人工演示顺序

请使用独立演示库，以下操作会真实改变该演示库中的借阅、库存及钱包。

1. 学生或教师登录，借阅一本有价格的图书；借阅历史可见图书名称和借阅编号。
2. 图书管理员登录“流通管理”，选择该笔借阅，点击“确认遗失”，核对书名、借阅人和服务器原价后确认。
3. 查看“遗失赔偿”：金额按确认时图书原价固定；借阅状态变为“已遗失·待赔偿”。总册数减 1，可借册数不变。
4. 借阅人登录“遗失赔偿”，查看本人的待支付账单与校园钱包余额。需要余额时，通过商店钱包充值后回到图书馆刷新。
5. 选择账单并确认支付，核对原价金额和本人钱包扣款提示。完成后账单“已结清”、借阅“已赔偿”，普通归还提醒不再包含该记录。
6. 到商店钱包刷新：余额同步减少原价金额，新增一条“图书赔偿”流水。管理员只可查全量赔偿记录，不可替借阅人扣款。
7. 如需演示零元图书，单独新增一本价格为 0 的测试书：按钮显示“确认结清”，无须充值，不扣款、不产生零元扣款流水。

本次开发验证没有在该演示库中生成遗失单或支付扣款，现有业务数据保留。支付、故障、权限与并发自动测试全部使用隔离的临时数据库或内存实例。

## 自动化验收范围

- 24 个内存并发请求争抢一本书、8 个 Access 并发请求争抢一本书：分别仅一个成功。
- 多副本上限、同一用户重复借阅、并发重复归还、批量竞争失败无部分借阅。
- 原价分金额、HALF_UP 舍入、价格快照、零元与金额溢出。
- 同一借阅确认遗失幂等、同一账单并发支付仅扣一次、重复查询和重启持久化。
- 余额不足、他人付款、无效会话、角色越权、伪造载荷、新消息分发及旧客户端兼容保护。
- 真实 Access 连接在扣款后注入流水写入故障，以及在最终提交前注入故障；验证余额、流水、账单和借阅状态全部回滚。
- 新界面角色差异、整数分显示、支付确认与断线不自动重试、单任务同步关联视图、遗失/赔偿记录不再触发归还提醒。

这些是当前单服务器共享仓库的并发正确性测试，不是多服务器或生产级吞吐量压测。实现与接口说明见 [图书赔偿与钱包对接](../docs/LIBRARY_COMPENSATION.md)。
